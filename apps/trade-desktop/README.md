# PoE Trade Companion

Приложение Windows и отдельный MCP stdio работают с одним локальным сервисом. Диапазоны статов, бюджеты, ссылки и журнал событий доступны через оба интерфейса.

## Запуск

1. Установите Node.js 24 LTS и зависимости через `npm ci`. Выполните `npm run build`.
2. Из корня репозитория выполните `powershell.exe -NoProfile -ExecutionPolicy RemoteSigned -File .\apps\trade-desktop\Install-TradeShortcut.ps1`. Скрипт соберёт Windows-лаунчер и создаст ярлык **PoE Trade** на рабочем столе текущего пользователя.
3. Откройте ярлык двойным щелчком. После установки пакета Electron первый запуск загружает его бинарный файл. Значок **PoE Trade** остаётся в трее после закрытия окна. Двойной щелчок по значку снова открывает окно.
4. Чтобы завершить фоновый процесс, выберите **Остановить сервис и выйти** в меню значка или выполните `./apps/trade-desktop/Start-Trade.ps1 -Stop`.

Для запуска из PowerShell используйте `./apps/trade-desktop/Start-Trade.ps1`. Ярлык связан с текущим расположением репозитория. При переносе репозитория удалите старый ярлык и выполните установку из нового расположения.

Клонирование с нуля, установка движка PoB и примеры конфигурации обоих MCP описаны в [инструкции по установке](../../docs/INSTALL.md).

Чтобы подключить отдельный MCP, зарегистрируйте команду `node` с абсолютным путём к `build/trade/mcp.js` первым аргументом. MCP и приложение используют один локальный сервис. Запустите настольное приложение для работы с его браузерной сессией. Если MCP первым запустил фоновый сервис, настольное приложение перезапустит его со встроенным браузером. Используйте одинаковые `POE_TRADE_HOME` и `POE_TRADE_PORT` в MCP и приложении.

## Торговые режимы

В разделе **Настройки → Лига с торгового сайта** можно выбрать игру, платформу и лигу. Текущая лига видна в шапке приложения. Приложение загружает список PoE Trade для каждой игры и платформы и при повторном открытии берёт его из локального кэша. Кнопка **Обновить лиги** запрашивает свежий список. Ссылку на готовый поиск можно вставить в том же разделе. В MCP за эти операции отвечают `trade_list_leagues` и `trade_scope_from_url`.

Во вкладке **Live Search** вставьте ссылку на выполненный поиск PoE Trade, укажите имя при необходимости и нажмите **Импортировать шаблон**. Игра и лига берутся из ссылки. Если сайт временно не отдаёт фильтры, приложение сохраняет ссылку и повторяет попытку при активации. Из карточки слота PoB шаблон можно создать кнопкой **Сохранить шаблон Live Search**. Если прямой Live Search отключён, откройте поиск из шаблона и включите Live Search на сайте.

Кнопка **Показать лоты** под поиском в **Комплекте PoB** и в результатах **Помощника** выводит первые объявления в порядке запроса. Карточки показывают цену, продавца, время выставления, характеристики и модификаторы. **Сравнить в PoB** рассчитывает, как лот меняет открытый билд PoE 1 при замене предмета в слоте поиска. Кнопка доступна, когда сайт вернул полный текст предмета. Для остальных лотов можно скопировать текст с сайта и вставить его в форму **Сравнить предмет в PoB**. Все результаты и действия по покупке доступны по ссылке на PoE Trade.

При настольном запуске прямые запросы лотов включены по умолчанию. Для взвешенных запросов откройте **Настройки → Сессия PoE Trade** и нажмите **Войти в Path of Exile**. Браузер хранит собственный профиль на этом компьютере и автоматически применяет действующую сессию после перезапуска. Поиск из MCP использует тот же сервис. **Выйти из аккаунта** очищает профиль входа и отключает активные подписки.

`POE_TRADE_ENABLED=false` оставляет переход по ссылке на торговый сайт. `POE_TRADE_LIVE_ENABLED=false` отключает прямые подписки. В режиме только MCP без настольного приложения доступны `POE_SESSION_ID`, `POE_TRADE_USER_AGENT` и `POE_TRADE_LIVE_ENABLED=true`. Прямые запросы зависят от доступности внутренних интерфейсов GGG. [Developer Docs GGG](https://www.pathofexile.com/developer/docs/index#available-resources)

При настроенном прямом Live Search нажмите **Активировать** на карточке шаблона. Подписка работает до нажатия **Пауза** или закрытия окна, из которого её запустили. Шаблон и журнал остаются в SQLite и доступны после перезапуска. В MCP сформированный шаблон сохраняет `trade_watch_save`, а ссылку импортирует `trade_watch_import`.

## Path of Building

Адаптер переиспользует PoB MCP для PoE 1. В разделе **Настройки → Path of Building** выберите папку XML-билдов и папку PoB с `HeadlessWrapper.lua` в корне или в `src`. Пути сохраняются в приложении. Новая папка билдов сразу используется источником **Файл в папке билдов PoB**, а адаптер переключает движок при следующей операции. Настройки по умолчанию учитывают `POB_DIRECTORY`, `POB_PATH` и `POB_FORK_PATH`. LuaJIT можно указать через `POB_CMD`.

Подпапки показаны в названиях файлов. Кнопка **Обновить список** перечитывает папку. Также можно загрузить код экспорта, ссылку или XML. Билды и их ревизии хранятся в памяти до остановки процесса. Сохранённые поиски сохраняются в SQLite.

В режиме «Подобрать похожие» проверяйте подсказки для модов, которым не нашлось однозначного ID. Режим апгрейда сохраняет веса и сортировку нативного PoB. Вставленный текст лота можно оценить в PoB для выбранного слота. Поисковые ссылки PoE 2 используют отдельный формат. Для расчёта экипировки PoE 2 потребуется отдельный адаптер PoB2.

Общий бюджет и бюджеты слотов используют английские названия из фильтра цены PoE Trade. Набор для каждой игры включён в приложение и доступен офлайн. Для диапазона без ограничения на валюту выберите эквивалент. [PoE 1](https://www.pathofexile.com/api/trade/data/filters) · [PoE 2](https://www.pathofexile.com/api/trade2/data/filters)

### Сохранённые комплекты

Во вкладке «Комплект PoB» раскрывающийся список показывает слот и экипированный предмет. При выборе слота видны его характеристики, модификаторы и отдельный бюджет. Кнопка **Создать поиск по выбранному слоту** формирует один запрос для этого слота. Пустые гнёзда самоцветов дерева скрыты.

Выберите лигу, слот, режим и бюджеты, затем нажмите «Сохранить комплект». Отдельный бюджет слота имеет приоритет над общим. Кнопка «Открыть» загружает сохранённую ревизию билда и восстанавливает параметры формы после перезапуска сервиса. Если в старом комплекте несколько слотов, список открывается на первом доступном. Вместе с комплектом в локальной SQLite сохраняется снимок билда. Переименование и удаление комплекта относятся к записи приложения. Исходный файл PoB и шаблоны Live Search используются независимо.

## Подключение локальных MCP к Codex

В разделе **Настройки → Локальные MCP в Codex** выберите `config.toml`, отметьте **Path of Building** и **PoE Trade**, затем откройте предпросмотр. Действие **Записать в config.toml** заменяет только отмеченные серверы. Приложение сохраняет предыдущую версию файла рядом с ним и отклоняет запись, если файл или параметры изменились после предпросмотра. После записи откройте новый сеанс Codex. Встроенный помощник PoE Trade продолжает использовать собственный список инструментов.

## Помощник Codex

Кнопка **Чат Codex** в шапке открывает боковую панель из любого раздела. Переключение разделов и сворачивание панели сохраняют переписку открытого окна. Помощник готовит подбор для выбранного слота PoB и читает шаблоны Live Search текущей лиги. Для уточнений он учитывает последние ответы в рамках той же лиги и ревизии билда. Текст запроса и ограниченные результаты инструментов передаются сервису Codex.

Чтобы сопоставить открытый билд с гайдами, публичными примерами игроков, ценами poe.ninja и статистикой GGG, включите **Искать гайды и открытые данные PoE**. Помощник покажет рекомендации, способы проверки в PoB и ссылки на использованные источники. [Руководство по исследованию, инструменты и готовые промпты](../../docs/assistant-poe-research.md)

Помощник может предложить сохранить поиск PoB, импортировать ссылку PoE Trade, поставить запущенный шаблон на паузу или удалить его. Проверьте имя, лигу и действие на карточке. При импорте можно открыть проверенный исходный поиск. Нажмите кнопку на карточке, чтобы применить предложенное изменение. Удаление запрашивает отдельное подтверждение и сохраняет журнал событий. Запуск подписки доступен на карточке во вкладке Live Search.

Для комплекта PoB можно попросить помощника сохранить текущие настройки, открыть, переименовать или удалить сохранённый комплект. Приложение применяет действие после подтверждения на карточке. Параметры нового комплекта берутся из формы PoB в момент запроса. При изменении выбранных слотов, лиги или бюджета подготовьте предложение заново.

После открытия комплекта попросите помощника подобрать апгрейды для выбранного слота с учётом его бюджета. На карточке результата показан бюджет запроса. Чтобы сохранить его, нажмите «Сохранить как шаблон Live Search», проверьте бюджет в подтверждении и нажмите «Сохранить шаблон». Сохранённый поиск появится во вкладке Live Search на паузе.

### Заметки для помощника

Откройте билд и найдите **Заметки для помощника** во вкладке **Комплект PoB**. Там можно добавить, исправить или удалить текст и нажать **Сохранить заметки**. Заметки хранятся в локальной SQLite приложения отдельно от PoB Notes. У комплектов с одним снимком билда общие заметки. При загрузке изменившегося экспорта откроется блок новой ревизии.

При обычном запросе или исследовании можно сообщить помощнику особенность билда, например «Для этого билда сохраняй 100% подавления чар при любых апгрейдах». Помощник автоматически добавляет подходящие выдержки из вашего сообщения после успешного ответа. Сохранённый текст включается в последующие запросы Codex для этого билда. При одновременном изменении редактор сохраняет набранный текст и предлагает обновить заметки перед сохранением.

Авторизуйте установленный Codex CLI командой `codex login`. В **Настройках → Codex CLI** выберите `codex.exe` и нажмите **Сохранить путь**. Чат доступен после успешной проверки `codex login status`. Если вы только что вошли в CLI, нажмите **Проверить готовность**. Сохранённый путь восстанавливается после перезапуска приложения.

Для настройки из PowerShell можно задать `POE_ASSISTANT_CODEX`. Путь, сохранённый в приложении, имеет приоритет. Кнопка **Сбросить путь** возвращает значение переменной среды, если она задана.

```powershell
$env:POE_ASSISTANT_CODEX = (Get-Command codex -CommandType Application).Source
./apps/trade-desktop/Start-Trade.ps1
```

Помощник использует операции чтения `assistant_pob.prepare_slots`, `assistant_pob.list_sets`, `assistant_trade.list_watches` и `assistant_trade.describe_trade_link`. Подтверждение доступно в окне, где был создан запрос. Повтор подтверждения с тем же ключом возвращает прежний результат, а предложение для изменившегося шаблона или комплекта нужно подготовить снова. В `service.log` компонент `assistant` записывает идентификатор запроса, выполненные инструменты, подтверждения, отказы и коды ошибок. Компонент `pob-sets` журналирует открытие и изменение комплектов, а `build-notes` — результаты сохранения. Тексты запросов и заметок, снимки билдов, URL и ключи в журнал не включаются.

Для сквозной проверки установленного Codex CLI запустите `npm run test:smoke:assistant` из репозитория после сборки. Параметр `-- --probe-proposals` проверяет действия с Live Search, а `-- --probe-sets` проверяет подтверждения комплектов. Проверка запрашивает модель через авторизованный CLI и использует отдельный экземпляр приложения с тестовыми данными. Для проверки восстановления без вызова модели запустите `node tests/smoke/pob-sets-restart.mjs`.

Полный сценарий от открытия комплекта до сохранения выбранного запроса можно повторить командой `node tests/smoke/assistant-set-watch-flow.mjs --real`. Укажите абсолютный путь к модулю Playwright в `POE_ASSISTANT_PLAYWRIGHT`. При необходимости задайте `POE_ASSISTANT_EDGE` и `POE_ASSISTANT_CODEX`. Тест выполняет два запроса Codex на тестовом билде в отдельном экземпляре приложения.

По умолчанию данные лежат в `%LOCALAPPDATA%/PoELocalTrade`. `POE_TRADE_HOME` и `POE_TRADE_PORT` позволяют выбрать другое расположение данных и локальный порт. В `service.log` записываются запуск сервиса, подключения интерфейса, операции PoB, обновления справочника лиг, торговые запросы и переходы состояния Live Search. Каждая новая запись содержит время UTC, компонент и событие. Cookie, URL поиска и содержимое билда в эти записи не включаются.
